# Personal Finance Analytics (MySQL + Tableau)

A MySQL database of 12 months of synthetic banking data (30 users, 72 accounts, ~11,000
transactions), with SQL reports and a Tableau dashboard for cash flow, spending trends,
overdrafts, recurring charges and unusual transactions.

The data is generated by a Python script, not hand-written. It includes bi-weekly paycheques,
rent, utilities, subscriptions, credit card payments and transfers between accounts. It also
includes 15 deliberately injected unusual purchases, so the anomaly query can be checked
against a known answer.

## Dashboard

A Tableau Public dashboard built on the exported CSVs in `exports/` is in progress. The build
steps are in [dashboard/TABLEAU.md](dashboard/TABLEAU.md).

## What the SQL does

| Query | Techniques |
|---|---|
| Monthly income, spending, net cash flow and savings rate per user | CTE, conditional aggregation |
| Running balance per account, starting from the opening balance | `SUM() OVER` with an explicit frame |
| Accounts that went into overdraft, with first date and lowest balance | Window function inside a CTE, `HAVING` |
| Category share of monthly spend and month-over-month change | `SUM() OVER (PARTITION BY)`, `LAG()` |
| Top 3 merchants per user | `RANK()` |
| Recurring charges (subscriptions, fixed bills) with annualized cost | `COUNT(DISTINCT)`, `HAVING` |
| Unusual-transaction detection | `AVG` / `STDDEV_SAMP` over a trailing window, named `WINDOW` |

### Anomaly detection

A purchase is flagged when it is both:
- more than 3 standard deviations above that user's average for the same category, and
- at least 3× their typical amount for that category.

The average and standard deviation are calculated from the user's **previous** purchases only
(`ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING`), so a large purchase can't raise its own
baseline. The 3× rule was added after the first version flagged small swings, such as a $52
movie night against a $33 average, in categories that barely vary.

**Results on the generated data** (seed 42): 14 of 15 injected anomalies caught (93% recall),
2 false positives (88% precision).

The one miss happened because the same user had an earlier injected anomaly in the same
category. That earlier purchase inflated the standard deviation. A median-based baseline, or
leaving already-flagged transactions out of the baseline, would fix this.

## Schema

```
users ──< accounts ──< transactions >── merchants
                            │
                            └──── categories (Income / Expense / Transfer)
```

- Amounts are signed: positive is money in, negative is money out.
- Transfers between a user's own accounts are their own category type, so they don't count as
  income or spending.
- Columns are `NOT NULL` with foreign keys, a `CHECK` that amounts are non-zero, and a unique
  (user, account type) pair.
- Indexes on `(account_id, transaction_date)` and `(category_id, transaction_date)` match how
  the window functions partition and sort.

## How to run

Requires MySQL 8.0.16+ (or MariaDB 10.6+) and Python 3.9+. Tested on MySQL 8.0 and MariaDB 10.11.

```bash
# 1. (Optional) regenerate the data. A pre-generated sql/02_seed_data.sql is included,
#    and the same seed always produces identical data.
python3 scripts/generate_data.py --users 30 --seed 42

# 2. Build the database and run the reports
mysql -u root -p < sql/01_schema.sql
mysql -u root -p < sql/02_seed_data.sql
mysql -u root -p < sql/03_views.sql
mysql -u root -p --table < sql/04_analytics.sql

# 3. Export CSVs for Tableau and check anomaly detection
pip install -r requirements.txt
python3 scripts/export_for_tableau.py --user root
```

**On Windows:** run step 2 in Command Prompt rather than PowerShell, because PowerShell doesn't
support `<`. Also use `python` instead of `python3`.

## Project structure

```
sql/
  01_schema.sql          tables, constraints, indexes
  02_seed_data.sql       generated data (do not edit by hand)
  03_views.sql           dashboard views, including the anomaly rule
  04_analytics.sql       reports
scripts/
  generate_data.py       synthetic data generator (standard library only)
  export_for_tableau.py  CSV export + anomaly precision/recall check
exports/                 CSVs for Tableau and anomaly ground truth
dashboard/               Tableau build notes
```
